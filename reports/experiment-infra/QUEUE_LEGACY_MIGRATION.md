## 3. Migration and reconciliation rule

A queue history containing `ENQUEUE_REFUSED` is historical. Such a row must never trigger another enqueue.

1. Only a BOUND row is fenced. It becomes `AMBIGUOUS` with `ambiguous_from=BOUND`, and the
   `LEGACY_REFUSED_FENCED` marker is written in the same transaction (one `BEGIN IMMEDIATE`).
   Interruption before COMMIT leaves the store bytes unchanged (tested).
2. The fence is applied on every entry that could advance the row: `queue_enqueue_attempted` (and so
   `release`), `queue_claim`, `queue_claim_idempotent` (fresh claim only), `queue_recover`
   (so `reconcile`), and the explicit `queue_migrate_legacy_refusals(folder)`. Each commits the fence,
   then refuses. Nothing is retried, resubmitted or released.
3. A CLAIMED row keeps its owner: it is reported `KEPT` and not written.
4. Idempotent: a second run reports `ALREADY_FENCED` and writes no bytes.
5. Existing legitimate records are not rewritten: the phase check runs before any write, and a
   legitimate run with no refusal history is unchanged (tested).
6. Damaged refusal events, a refusal on a row in another phase (INTENT, RETRYABLE, ...), an orphan
   history, or a truncated store raise `REGISTRY_UNREADABLE` with no write. The store open message
   for corrupt files now also uses `REGISTRY_UNREADABLE`. Nothing is repaired.
7. No flag, environment variable or parameter overrides the fence (tested by signature and env
   checks). `queue_enqueue_outcome` no longer accepts `ENQUEUE_REFUSED`.

Known schema step: the first open of a legacy store by current code adds `queue_submitters`. This
is additive, not the fence, and the tests perform it once before taking byte baselines.

## 4. Daemon identity (P7.4)

- `PrivatePueue.peer_identity()`: SO_PEERCRED of a probe connection gives the listener pid and uid.
  `/proc/<pid>/exe` is hashed (must equal the pinned pueued), start ticks come from `/proc/<pid>/stat`,
  and the socket device and inode must not change during the probe.
- `start()` records the peer and refuses if it is not the process this object started.
- `verify_peer()` / `daemon_identity()`: live peer must equal the started peer (pid, start ticks,
  exe hash, socket dev/inode); the queue instance is the state certificate.
- `issue_callback()` / `verify_callback()`: a callback must match the CLAIMED row on expected queue
  instance, task ID, worker index (`worker_id`), run attempt and ownership fence, and its peer must be
  the connected daemon. Refusals write nothing.

Can prove: the process that answers the private socket probe is the pinned binary started by this
object, and the callback was issued by that process.
Cannot prove: the pueue client's later connections are bound to that peer (TOCTOU gap); the queue
instance is an on-disk certificate, not a peer-supplied secret; a same-user attacker can replace the
state directory. Trusted transport boundary still required: each request must be authenticated on
the connection that carries it (per-daemon secret held by the verified process, or pidfd-bound
connection), and the state and socket directories must be writable only by the owner.

## 6. Residuals

- The fence is a local, same-account control. It does not stop a writer with access to the store.
- A CLAIMED row with refusal history is kept as is (owner verified elsewhere). It is not re-verified here.
- Identity is not transport-authenticated (section 4). QUEUE_READY stays BLOCKED.
- The fixtures were produced with a development build on one host. The generator is `tests/fixtures/legacy_e90e3b1/generate.py`
  and needs the pinned binaries to rerun.
