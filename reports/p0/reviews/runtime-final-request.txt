# Review: commit `95f7b08`, runtime and daemon fingerprinting

**Scope:** `scripts/runtime_identity.py`, `tests/test_runtime_identity.py`, `.github/workflows/ci.yml`, `.python-version`, and `docs/OPERATIONS.md`. I reviewed only the supplied source and ran nothing. I make no claim about whether the daemon, Pueue, or Herdr is ready.

**Verdict:** I found no confirmed critical defects. The script fails closed on the paths it handles, and the docs correctly say a match is not proof of execution. There are two high-severity gaps, and both matter before this fingerprint is used as a gate for queued execution. Neither is exploitable while the P0 hold blocks queued runs.

---

## High

### H1. The fingerprint can match while the runtime the code actually uses differs
`identity()` covers the executable bytes, `sys.prefix`/`sys.base_prefix`, and the (name, version) pairs from `importlib.metadata.distributions()`. Each of the following changes what code runs without changing the fingerprint:

- **`PYTHONPATH` or extra `sys.path` entries holding modules without dist-info.** For example, a bare `numpy/` directory that shadows the installed one. It has no metadata, so it is invisible to `distributions()`.
- **Code that runs at startup:** `sitecustomize`/`usercustomize`, `.pth` lines, `PYTHONSTARTUP`-style hooks, `LD_PRELOAD`, and `LD_LIBRARY_PATH`.
- **Shared-library builds.** When the interpreter is built with `--enable-shared` (actions/setup-python builds are; many pyenv and conda configurations can be), `executable_sha256` hashes only a small launcher. `libpython3.10.so` and the whole stdlib are not covered.
- **Interpreter flags** (`-I`, `-E`, `-s`, `-S`, `-O`, `-X`), which change import behaviour. Some show up indirectly through the package list, but most do not.
- **Package contents.** The docs disclose this one.

**Impact:** `--expect` returns 0 for two workers whose imported code differs materially. That defeats the stated purpose of comparing runtimes.

**Action:**
- Add these fields: `sys.path`, `sys.flags`, a hash of `sys.version` together with `sysconfig.get_config_var('LDLIBRARY'/'Py_ENABLE_SHARED')`, a hash of the resolved libpython (if shared), the stdlib directory, and the presence of `sitecustomize`/`usercustomize`.
- Fingerprint an allowlist of environment variables: `PYTHON*`, `LD_*`, `PATH`, `VIRTUAL_ENV`.
- Optionally hash the `RECORD` files of the installed distributions. This is cheap and catches most in-place edits.
- Bump `schema_version`.

### H2. The fingerprint process is not the job process, and nothing binds the two
The docs say to run `runtime_identity.py --expect` inside the daemon. What that measures is the environment of that one invocation. The job is a separate invocation with its own argv, flags, cwd, and possibly its own environment. The output also contains no run ID, task ID, nonce, or timestamp, so a preserved "match" cannot be tied to a specific run. This sits directly on one of the listed P0 blockers ("provenance binding").

**Action:**
- Have the worker wrapper (the supervisor that `exec`s the job) compute the fingerprint in-process immediately before `exec`, using the same interpreter and flags.
- Record the fingerprint in the run's SQLite registry along with the run ID and the owner token.
- Accept a `--nonce` or `--run-id` argument and echo it in the output, so preserved evidence can be bound to a run.
- Until that exists, the docs should state outright that a standalone match is not evidence for any particular run. The current wording comes close but stops short of that.

## Medium

### M1. `sys.executable` is not guaranteed to be the running image
On Linux, CPython 3.10's path calculation derives `sys.executable` from `argv[0]`, searching `PATH` when `argv[0]` has no slash. It does not use `/proc/self/exe`.

For example, `exec -a python3 /opt/other/python3.10 script.py` runs one binary while the script hashes whatever `python3` resolves to on `PATH`. A supervisor that sets `argv[0]` can trigger the same mismatch.

**Action:** On Linux, hash `os.readlink('/proc/self/exe')`. Block if that path differs from `Path(sys.executable).resolve()`, or if it ends in ` (deleted)`.

### M2. The test cannot tell a fail-closed block from a crash
`assertNotEqual(returncode, 0)` also passes on an unhandled traceback, which exits with 1. A regression that broke `--expect`, for instance by raising `TypeError`, would still pass.

**Action:** Assert `returncode == 2` and `'BLOCKED: interpreter fingerprint mismatch' in stderr`, and assert that stdout is empty on mismatch. Add cases for:
- a malformed JSON expect file
- a missing expect file
- a non-object JSON value
- changes to `packages_sha256`, `executable_sha256`, and `prefix`
- a `PYTHONPATH` difference, which will fail until H1 is fixed and serves as a regression marker

### M3. Some failure paths escape the `BLOCKED` contract
These cases exit with 1 and a traceback instead of 2 and a `BLOCKED` message. They still fail closed, but callers that check for exactly 2 or for the message will misclassify them:

- `TypeError` when `sys.executable` is `None` (embedded interpreters).
- `TypeError` from `sorted()` on broken distributions. A missing `Version` gives `None`, which cannot be compared with `str`. On 3.10, missing metadata can also raise inside `d.metadata`.
- `RecursionError` on a deeply nested expect file.

**Action:** Catch `Exception` around `identity()` and the comparison, map it to `BLOCKED` with exit 2, and normalise `None` to `''`.

### M4. The docs undermine the "same absolute interpreter" rule
The docstring says "use the same absolute interpreter." `OPERATIONS.md` says `python scripts/runtime_identity.py`, while every other command in the docs and CI uses `python3`. The capture step is trust-on-first-use: if `python` resolves to the wrong environment, every later comparison faithfully confirms the wrong baseline. The docs also never say to redirect the output to a file, or which cwd, flags, and environment to use.

**Action:** Document the exact command, e.g. `/abs/path/to/venv/bin/python3 -I scripts/runtime_identity.py > fingerprint.json`. Use whichever flags the worker will actually run with, because `-I` changes what gets measured. Also require operators to check the recorded `executable` and `prefix` by eye before trusting the baseline.

### M5. CI does not run on this branch's pushes
The push trigger is `main` and `feat/**`. Pushes to `fix/p0-reliability-remediation` are validated only if a PR is open.

**Action:** Add `fix/**` to the trigger, or trigger on all branches.

### M6. Actions are pinned by mutable tag
`actions/checkout@v4` and `actions/setup-python@v5` are pinned by tag. `contents: read` limits the damage, but pinning to full commit SHAs is the standard fix.

## Low / notes
- **No mismatch detail.** On mismatch the script prints no information about which keys differ. Emitting the differing key names (not the values) to stderr would help operators without leaking anything meaningful.
- **Self-attestation only.** Code in a compromised environment (via `.pth` or `sitecustomize`) runs before the script and can falsify the output. The docstring says "not a sandbox"; it should also say "not tamper-evident."
- **Shadowing.** `sys.path[0]` is `scripts/`, so a stray `scripts/json.py` or `scripts/hashlib.py` would shadow the stdlib module inside the fingerprinting tool itself. Keep that directory free of stdlib names, or check for it in a test.
- **Pinned version.** I could not verify from the source alone that `3.10.21` exists in the setup-python version manifest. If it doesn't, CI fails loudly rather than silently, so the risk is limited, but confirm it.
- **Import ordering.** The `importlib.metadata` import runs before the 3.10 version check. On Python 3.7 or older, the script dies with `ImportError` (exit 1) instead of printing the `BLOCKED` message. Moving the import inside `identity()` fixes this.

I did not assess `researchctl.py`, the registry or reconcile code, the bootstrap scripts, the Pueue setup, or any actual daemon behaviour. None of them were supplied.

#!/usr/bin/env python3
"""Compare diagnostic interpreter fingerprints; this is not an attestation.

Use the same absolute interpreter, flags, environment and working directory for
CLI and worker. A standalone match is not evidence of any particular run.
"""
import argparse
import hashlib
import json
import os
from pathlib import Path
import platform
import re
import sys
import sysconfig


def sha_file(path):
    digest = hashlib.sha256()
    with Path(path).open('rb') as stream:
        for block in iter(lambda: stream.read(1024 * 1024), b''):
            digest.update(block)
    return digest.hexdigest()


def identity():
    import importlib.metadata
    if not sys.executable:
        raise ValueError('interpreter executable unavailable')
    executable = Path(sys.executable).resolve(strict=True)
    if sys.platform.startswith('linux'):
        proc_executable = os.readlink('/proc/self/exe')
        if proc_executable.endswith(' (deleted)') or Path(proc_executable).resolve(strict=True) != executable:
            raise ValueError('sys.executable differs from running image')
    libpython = []
    if sys.platform.startswith('linux'):
        mappings = set()
        with open('/proc/self/maps', encoding='utf-8') as maps:
            for line in maps:
                parts = line.split(None, 5)
                if len(parts) < 6:
                    continue
                path = parts[5].strip()
                if re.match(r'^libpython[0-9].*\.so(?:\.[0-9]+)*$', Path(path.removesuffix(' (deleted)')).name):
                    if path.endswith(' (deleted)'):
                        raise ValueError('mapped libpython is deleted')
                    mappings.add(str(Path(path).resolve(strict=True)))
        libpython = [{'path': path, 'sha256': sha_file(path)} for path in sorted(mappings)]
    packages = sorted((str(d.metadata.get('Name') or ''), str(d.version or ''))
                      for d in importlib.metadata.distributions())
    packages_json = json.dumps(packages, separators=(',', ':'), ensure_ascii=True)
    flag_names = ('debug', 'inspect', 'interactive', 'optimize', 'dont_write_bytecode',
                  'no_user_site', 'no_site', 'ignore_environment', 'verbose', 'bytes_warning',
                  'quiet', 'hash_randomization', 'isolated', 'dev_mode', 'utf8_mode',
                  'warn_default_encoding', 'safe_path', 'int_max_str_digits')
    build = {'version_sha256': hashlib.sha256(sys.version.encode()).hexdigest(),
             'ldlibrary': sysconfig.get_config_var('LDLIBRARY'),
             'py_enable_shared': sysconfig.get_config_var('Py_ENABLE_SHARED')}
    return {'schema_version': 2, 'executable': str(executable), 'executable_sha256': sha_file(executable),
            'python_version': platform.python_version(), 'implementation': platform.python_implementation(),
            'prefix': str(Path(sys.prefix).resolve()), 'base_prefix': str(Path(sys.base_prefix).resolve()),
            'cwd': str(Path.cwd()), 'sys_path': list(sys.path),
            'flags': {name: getattr(sys.flags, name) for name in flag_names if hasattr(sys.flags, name)},
            'stdlib': sysconfig.get_path('stdlib'), 'build': build, 'libpython': libpython,
            'startup_modules_loaded': {name: name in sys.modules for name in ('sitecustomize', 'usercustomize')},
            'packages_sha256': hashlib.sha256(packages_json.encode()).hexdigest()}


def main():
    parser = argparse.ArgumentParser(description=__doc__)
    parser.add_argument('--expect', type=Path, help='Compare to a previously saved JSON fingerprint')
    args = parser.parse_args()
    if sys.version_info < (3, 10):
        print('BLOCKED: Python 3.10 or newer required', file=sys.stderr)
        return 2
    try:
        actual = identity()
        if args.expect:
            expected = json.loads(args.expect.read_text(encoding='utf-8'))
            if not isinstance(expected, dict) or actual != expected:
                print('BLOCKED: interpreter fingerprint mismatch', file=sys.stderr)
                return 2
        print(json.dumps(actual, sort_keys=True, indent=2))
        return 0
    except Exception as exc:
        print('BLOCKED: cannot fingerprint runtime: {}'.format(type(exc).__name__), file=sys.stderr)
        return 2


if __name__ == '__main__':
    sys.exit(main())

--- tests/test_runtime_identity.py ---
import json
import os
from pathlib import Path
import subprocess
import sys
import tempfile
import unittest

SCRIPT = Path(__file__).resolve().parents[1] / 'scripts' / 'runtime_identity.py'

class RuntimeIdentityTests(unittest.TestCase):
    def run_identity(self, *args, env=None):
        return subprocess.run([sys.executable, str(SCRIPT), *args], text=True, capture_output=True, env=env)

    def test_matching_and_changed_interpreter_identity(self):
        snapshot = self.run_identity()
        self.assertEqual(snapshot.returncode, 0, snapshot.stderr)
        record = json.loads(snapshot.stdout)
        self.assertEqual(record['schema_version'], 2)
        self.assertEqual(len(record['executable_sha256']), 64)
        self.assertIsInstance(record['sys_path'], list)
        self.assertIsInstance(record['flags'], dict)
        self.assertIn('stdlib', record)
        self.assertIn('libpython', record)
        with tempfile.TemporaryDirectory() as temp:
            path = Path(temp) / 'expected.json'
            path.write_text(snapshot.stdout)
            self.assertEqual(self.run_identity('--expect', str(path)).returncode, 0)
            for field in ('packages_sha256', 'executable_sha256', 'prefix'):
                with self.subTest(field=field):
                    modified = dict(record, **{field: 'invalid'})
                    path.write_text(json.dumps(modified))
                    result = self.run_identity('--expect', str(path))
                    self.assertEqual(result.returncode, 2)
                    self.assertIn('BLOCKED: interpreter fingerprint mismatch', result.stderr)
                    self.assertEqual(result.stdout, '')
            path.write_text(snapshot.stdout)
            env = dict(os.environ, PYTHONPATH=str(Path(temp) / 'extra'))
            result = self.run_identity('--expect', str(path), env=env)
            self.assertEqual(result.returncode, 2)
            self.assertIn('BLOCKED: interpreter fingerprint mismatch', result.stderr)
            self.assertEqual(result.stdout, '')
            optimized = subprocess.run([sys.executable, '-O', str(SCRIPT), '--expect', str(path)],
                                       text=True, capture_output=True)
            self.assertEqual(optimized.returncode, 2)
            self.assertIn('BLOCKED: interpreter fingerprint mismatch', optimized.stderr)
            self.assertEqual(optimized.stdout, '')
            for data in ('{', '[]'):
                path.write_text(data)
                result = self.run_identity('--expect', str(path))
                self.assertEqual(result.returncode, 2)
                self.assertIn('BLOCKED:', result.stderr)
                self.assertEqual(result.stdout, '')
            result = self.run_identity('--expect', str(Path(temp) / 'missing'))
            self.assertEqual(result.returncode, 2)
            self.assertIn('BLOCKED:', result.stderr)
            self.assertEqual(result.stdout, '')

    @unittest.skipUnless(sys.platform.startswith('linux'), 'Linux /proc check')
    def test_spoofed_argv0_is_blocked(self):
        result = subprocess.run(['bash', '-c', 'exec -a /bin/false "$1" "$2"', '_',
                                 sys.executable, str(SCRIPT)], text=True, capture_output=True,
                                env=dict(os.environ, PYTHONHOME=sys.base_prefix))
        self.assertEqual(result.returncode, 2, result.stderr)
        self.assertIn('BLOCKED:', result.stderr)
        self.assertEqual(result.stdout, '')

# Operator runbook

**P0 safety hold:** workspace bootstrap, queued runs, and official runs are blocked pending reconciliation, process containment, authenticated approval, provenance binding, and independent validation. Do not use this starter for GPU workloads. Local CPU diagnostics only. The commands below describe intended future operation where applicable.

## Prerequisites and setup
Linux server (headless), SSH, Python 3.10.21 (the pinned development runtime; 3.10+ supported), git, jq, bash, Herdr TUI. Optional: Pueue/pueued, uv, MLflow, nvidia-smi, nvtop, btop. Most tools can use user space; NVIDIA driver and Docker GPU runtime may need administrator installation.

1. Inspect the host and agent dependencies: python3 scripts/researchctl.py doctor.
2. Install Herdr via its published install documentation (review script before executing).
3. Start Herdr interactively once, then detach. For supervised installations consider its headless server command and a user service.
4. Edit config/projects.json so project directories are existing Git checkouts; do not use the bootstrap as a cloning tool.
5. Run: RESEARCH_ROOT=$HOME/research bash scripts/bootstrap-herdr.sh
6. Install and authenticate agent CLIs separately; only then run herdr integration install codex/claude/hermes and check herdr integration status.
7. Find an *idle shell* pane with herdr pane list, then run herdr agent start <name> --kind codex --pane <id>.
8. Optionally initialize the one global Pueue GPU queue via scripts/setup-gpu-queue.sh.
9. Optionally install and run MLflow bound to 127.0.0.1; use SSH local port forwarding to view.
10. Test a CPU diagnostic run and inspect metadata/logs before running any GPU workloads.

A matching fingerprint does not authorize queue execution or scientific claims.

## Run registry and recovery (CPU diagnostics only)

Each new run uses a per-run SQLite registry with a one-time owner token and an event history. SQLite state and committed result are authoritative; the JSON result and status are compatibility projections and can be stale after interruption. `python3 scripts/researchctl.py reconcile --project <id> --run-id <id>` is read-only. It reports UNKNOWN for claims or processes whose completion is not proven; repeat inspection does not reclaim a run. Do not delete registry files or legacy `execution.claim` directories to retry. Preserve them and investigate the original supervisor and all descendants, then submit a new run only after an operator verifies that the old workload is no longer running. Automatic reclaim and queue task-ID reconciliation are not implemented. This protocol is for a trusted single host and supported local filesystems with working SQLite locking and fsync, not a distributed lock or an authentication boundary. Queued and official execution remain blocked.

Without verified process containment, the runner records `UNKNOWN` for the overall run after any leader exit, including an exit code of zero, failure or interruption. `result.json` and the registry preserve the separate leader outcome and exit code; neither proves that detached descendants stopped or a GPU slot is safe. `UNKNOWN` is never permission to retry. Diagnostic commands whose leader exits zero return status 2 to signal the unresolved containment state. The registry records child PID, Linux boot ID, and process start ticks when available for investigation only; those values do not establish containment. The runner refuses a non-default inherited SIGCHLD disposition so that its unreaped process-group leader cannot be silently reaped by another handler.
